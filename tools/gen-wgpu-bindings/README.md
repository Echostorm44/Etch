# Etch.BindingsGen

Generates C# P/Invoke bindings from wgpu-native C headers using ClangSharp.

## Overview

This tool invokes ClangSharpPInvokeGenerator to parse the WebGPU C headers (`webgpu.h` and `wgpu.h`) and generate type-safe C# P/Invoke bindings. The generated bindings use `LibraryImport` (source-generated interop) for AOT compatibility.

## Usage

```bash
dotnet run --project tools/gen-wgpu-bindings -- generate [options]
```

### Options

| Option | Default | Description |
|--------|---------|-------------|
| `--output <dir>` | `src/Etch.Gpu.Native/Generated` | Output directory for generated files |
| `--namespace <ns>` | `Etch.Gpu.Native` | C# namespace for generated code |
| `--class <name>` | `WebGPU` | Class name for generated static methods |
| `--header-dir <dir>` | `native/wgpu-native/include` | Directory containing C headers |

### Examples

```bash
# Generate with defaults
dotnet run --project tools/gen-wgpu-bindings -- generate

# Generate to custom output directory
dotnet run --project tools/gen-wgpu-bindings -- generate --output ./generated

# Show help
dotnet run --project tools/gen-wgpu-bindings -- --help
```

## When to Regenerate

Regenerate bindings when:

1. **wgpu-native version bump** - When upgrading to a new wgpu-native release, update `native/wgpu-native/VERSION` and regenerate bindings.
2. **WebGPU spec changes** - If the WebGPU specification adds new API surfaces.
3. **After modifying headers** - Any changes to files in `native/wgpu-native/include/` require regeneration.

## Diff Review Process

Every generated file carries this header:

```csharp
// ⚠️ AUTO-GENERATED by ClangSharpPInvokeGenerator - DO NOT EDIT DIRECTLY ⚠️
```

**All diffs are hand-inspected before merge.** The review checklist:

- [ ] New function bindings look correct (correct parameter types, return types)
- [ ] Handle type remappings are applied (`WGPUDevice` → `DeviceHandle`, etc.)
- [ ] Struct layouts match C headers exactly ( sizes, alignment)
- [ ] No manual edits to generated files (regenerate instead)
- [ ] New warnings from AOT/trimming are addressed

## Generated Output

The tool produces three files per binding set:

| File | Contents |
|------|----------|
| `WebGPU.Types.cs` | Handle type definitions (`InstanceHandle`, `DeviceHandle`, etc.) |
| `WebGPU.Structs.cs` | C struct definitions as C# layouts |
| `WebGPU.Generated.cs` | `LibraryImport` P/Invoke method declarations |

## Architecture

The generator parses C headers and applies these transformations:

1. **Opaque pointer → typed handle** - `WGPUDeviceImpl*` becomes `DeviceHandle` struct
2. **C enum → C# enum** - `WGPUPowerPreference` stays as enum
3. **C struct → C# struct** - `WGPUBufferDescriptor` becomes `[StructLayout]` class
4. **C function → LibraryImport** - `wgpuDeviceCreateBuffer` becomes P/Invoke method

## Troubleshooting

### "libclang not found"

Ensure libclang is installed and accessible in `PATH`. ClangSharp looks for `libclang` DLL/shared library.

### "Binding generation failed"

Check that headers in `native/wgpu-native/include/` are complete and match the VERSION file.

### "AOT warnings on generated code"

The generated code uses `LibraryImport` which is AOT-safe. If warnings appear, verify:
- No `DllImport` attributes exist (should all be `LibraryImport`)
- All native types have correct `[StructLayout]` attributes
